## 3. Ключевые решения

- Куча упорядочена по `(at, seq)`, поэтому элементы сразу выходят в нужном
  порядке: сначала по времени срабатывания, при равенстве — по порядку назначений.
- `seq` — уникальный номер назначения. Он решает сразу две задачи: задаёт порядок
  при равных `at` и позволяет отсеивать устаревшие записи.
- Ленивое удаление: при повторном `SET` и при `CANCEL` старая запись остаётся в
  куче и отсеивается при извлечении — сравнением с активным назначением по ссылке
  (`is`), что эквивалентно сравнению `seq`.
- Активные таймеры — в `dict id -> назначение`, поэтому `CANCEL` за O(1).
- Граница `<= to` включает момент `to`; сам `SET` не срабатывает.
- `heap_size = active + stale`; куча уменьшается только на `ADVANCE`.

## 4. Оценки сложности

| операция | своя куча | эталон (dict + сортировка) |
|---|---|---|
| `SET` | O(log n) | O(1) |
| `CANCEL` | O(1) | O(1) |
| `ADVANCE` | O((k + s) log n) | O(m log m) |
| память | O(всех назначений) | O(активных) |

`n` — записей в куче, `m` — активных таймеров, `k` — сколько сработало,
`s` — сколько устаревших вынуто при этом `ADVANCE`.

## 5. Вероятные вопросы и ответы

- **Почему ленивое удаление, а не удаление по индексу?** Не нужно хранить индексы
  и обновлять их при каждом перемещении; `SET`/`CANCEL` дешевле, платим памятью.
- **Как понимаете, что запись устарела?** Сравниваем запись из кучи с текущим
  активным назначением того же `id`: если это не тот же объект — устарела.
- **Почему `heapify` за O(n)?** Просеивание снизу вверх: сумма высот поддеревьев
  ≤ 2n, а не n·log n.
- **Чем `replace_top` отличается от `pop` + `push`?** Одно просеивание вниз вместо
  двух проходов; O(log n) за один проход.
- **Почему цикл в `ADVANCE` нельзя прервать раньше времени?** Сверху может лежать
  устаревшая запись, а ниже — валидная с тем же `at`.
- **Почему куча может быть больше числа активных таймеров?** Устаревшие записи не
  удаляются физически. В долго живущей системе нужна периодическая очистка.
- **Почему min-куча?** Нужны самые ранние моменты — минимальные `at`.
- **Как обеспечена кастомизация?** Флаг `min_heap` и `key`, сравнение через `_before`.

## 6. Возможные правки на месте

- Поменять направление: `BinaryHeap(min_heap=False)`.

- Сменить формат вывода (например, объекты `{"id": ..., "at": ...}`).
