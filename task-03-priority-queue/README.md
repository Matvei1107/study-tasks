# Задача №3. Очередь с приоритетом — вариант 6: «Таймеры с переносом и отменой»

Своя бинарная куча на массиве (без `heapq` и готовых куч) и решение на ней
варианта 6 из методички.

## Условие варианта

Обрабатываются команды:

| Команда | Смысл |
|---|---|
| `SET <id> <at>` | назначить таймеру `id` момент `at`; прежнее назначение того же `id` заменяется |
| `CANCEL <id>` | отменить активный таймер; отсутствующий `id` игнорируется |
| `ADVANCE <to>` | продвинуть модельное время до `to` и выдать сработавшие таймеры |

Правила:
- начальное время `0`; `at >= текущего времени`, `to` не убывает;
- `SET` сам по себе таймер не запускает — срабатывание делает только `ADVANCE`,
  причём граница `to` включается (`at <= to`);
- сработавшие выдаются по моменту срабатывания, при равенстве — по порядку назначений;
- сработавший или отменённый `id` можно назначить заново;
- конец входа время не продвигает.

## Подход

- Куча хранит назначения, упорядоченные по `(at, seq)`, где `seq` — уникальный
  номер назначения: он же даёт порядок при равных `at`, он же позволяет отсеивать
  устаревшие записи.
- Активные таймеры лежат в словаре `id -> назначение`.
- При переносе и отмене старая запись остаётся в куче и отсеивается при
  извлечении (ленивое удаление).
